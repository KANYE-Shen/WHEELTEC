# 算法、地图与陌生环境验证

更新：2026-10-23。本页解释当前工程、地图文件、陌生房间验证和实车迁移。多场景实测见 [验证记录](../setup/verification/unknown_rooms/README.md)。

## 1. 算法放在哪里，分别解决什么问题

| 环节 | 当前方法与作用 | 项目文件 |
| --- | --- | --- |
| 边走边建图 | SLAM Toolbox：激光扫描匹配修正里程计，识别回环，用 Ceres 优化位姿图，输出二维地图 | [slam.yaml](config/slam.yaml) |
| 自己决定去哪里看 | 前沿探索：找已知空地与未知区域的边界，八邻域聚类后选安全接近点，按边界长度和行驶距离评分；可达路径仍用四邻域，避免斜穿障碍角 | [frontiers.py](../src/wheeltec_explore/wheeltec_explore/frontiers.py) |
| 管理探索任务 | 访问记录、失败重试、完成判断、保存和返回起点 | [node.py](../src/wheeltec_explore/wheeltec_explore/node.py)、[policy.py](../src/wheeltec_explore/wheeltec_explore/policy.py) |
| 规划与行驶 | Nav2 中的 NavFn A* 规划路径；Regulated Pure Pursuit 跟踪路径，并结合代价图、碰撞检查和等待重规划 | [nav2.yaml](config/nav2.yaml)、[navigate_wait.xml](config/navigate_wait.xml) |
| 已存地图内定位 | AMCL：根据激光、里程计和已有地图估计位置与朝向 | [nav2.yaml](config/nav2.yaml) |

探索算法是本项目源码；SLAM Toolbox、Nav2 是已安装的上游 ROS 包，没有把整套上游源码复制到 `src/`。当前没有 RL 模型。[探索实现说明](../src/wheeltec_explore/README.md)

算法依据：[SLAM Toolbox Humble](https://github.com/SteveMacenski/slam_toolbox/tree/humble)、[NavFn Humble](https://api.nav2.org/nav2-humble/html/classnav2__navfn__planner_1_1NavFn.html)、[RPP Humble](https://github.com/ros-navigation/navigation2/tree/humble/nav2_regulated_pure_pursuit_controller)、[AMCL Humble](https://github.com/ros-navigation/navigation2/tree/humble/nav2_amcl)。

## 2. 小车把地图记成什么

运行中的 `/map` 是 OccupancyGrid：带坐标原点、米/格分辨率和宽高的二维数组。本项目通常以 `-1` 表示未知、`0` 表示空地、`100` 表示占据；这是当前建图链路的编码约定。分辨率为 0.05 米，一格表示 5×5 厘米。它记录几何可通行性，尚未标注“床”“桌子”等物体语义。[消息定义](https://github.com/ros2/common_interfaces/blob/humble/nav_msgs/msg/OccupancyGrid.msg)、[地图元数据](https://github.com/ros2/common_interfaces/blob/humble/nav_msgs/msg/MapMetaData.msg)、[Nav2 地图读写实现](https://github.com/ros-navigation/navigation2/blob/humble/nav2_map_server/src/map_io.cpp)

一次保存产生这些文件：

| 文件 | 保存内容与用途 |
| --- | --- |
| `room.pgm` | 黑白灰栅格图；黑为障碍、白为空地、灰为未知 |
| `room.yaml` | 图像名称、分辨率、原点、判定阈值，供地图加载 |
| `room.posegraph`、`room.data` | SLAM 位姿图及关联扫描数据，供继续建图或图优化 |
| `room.metadata.json` | 本项目保存的用户参考方向等信息 |
| `room.exploration.json` | 自主探索任务状态与结果；自主探索时生成 |
| `room.simulation.json` | 普通自主探索生成的仿真布局、起点及来源哈希，供下次加载地图时恢复同一虚拟房间 |

栅格图是建图结果；位姿图是 SLAM 的内部关联数据。它们都不等于按时间保存了整个扫描过程。[保存实现](save_map.py)、[探索说明](../src/wheeltec_explore/README.md)、[SLAM Toolbox 保存接口](https://github.com/SteveMacenski/slam_toolbox/blob/humble/README.md)、[Nav2 Map Server](https://github.com/ros-navigation/navigation2/blob/humble/nav2_map_server/README.md)

日常操作默认把地图保存到 `/home/wheeltec/wheeltec_sim_ws/data/maps`；自动检查的地图保存在 `data/runs/<实验目录>`，不改变用户的 `latest.json`。普通操作最近保存的地图以 `latest.json` 中的 `map_yaml` 为准。Windows 可在资源管理器地址栏粘贴 `\\wsl.localhost\WHEELTEC-Ubuntu-22.04\home\wheeltec\wheeltec_sim_ws\data\maps`。`latest.json` 指向最近地图；[项目小地图样例](../data/samples/room-25m2/map.yaml) 可直接查看。

## 3. 与强化学习的关系

推荐先把 RL 放在“下一步去哪里探索”这一层：输入当前地图、位置、已访问区域，输出一个探索目标，仍由 SLAM Toolbox 建图、Nav2 行驶。奖励可考虑新增正确观测面积、耗时、路程和碰撞；与现有前沿探索在相同测试房间比较。这是后续研究方案，尚未实现。

[Active Neural SLAM 原作者工程](https://github.com/devendrachaplot/Neural-SLAM) 提供分层思路：全局策略选远目标，再结合规划和局部策略。它使用 RGB 神经建图与 Habitat 等依赖，不能作为当前二维雷达 ROS 工程的直接替换；适合参考分层和实验设计。[论文](https://arxiv.org/abs/2004.05155)

训练可以在电脑完成，实车只运行训练好的策略和其他算法；届时仍须测量 RDK X5 的计算负载。

## 4. 如何证明陌生环境里也能工作

目前通过的是固定 25 平方米场景的探索、保存、返回等闭环。[已有结果](../setup/verification/exploration/result.json) 中已观察空地 `22.713 m²` 是面积，不能直接称为覆盖率；内部的最小面积 8 m²、前沿长度阈值 0.25 m 和完成状态，也不能单独证明整个房间测绘完整。

现在已有原房间、L形、家具遮挡、弯通道、凹角五类布局，每类三个具名起点。每次从空白地图开始，算法只能接收传感器与估计地图，不能读取评估真值。完整批次使用原房间起点0，加四种新布局各三个起点，共13组；所有结果和源码哈希保留。

评估器用初始位姿确定米制刚体变换，不按最终地图重新拟合或缩放。正确空地覆盖率以真值中可达的安全车体中心为分母；未知和图外不算覆盖。真实可见墙面由布局的无遮挡视线确定，漏扫区域仍在分母内。轮廓误差分别求两个方向的95分位，再取最大值。还报告假空地、几何投影重叠、返航、耗时和路程。

试验门槛为正确可达空地覆盖率≥95%、双向轮廓95分位≤10cm、可见轮廓覆盖率≥95%、无几何重叠；新布局返航误差<20cm。内部completed与这些条件分别记录。仿真真值必须在任务期间连续、时间戳递增且在终点新鲜；断流后返航和安全结果为不可用，不能继续通过。[评分定义和命令](validation.md)

## 5. 从仿真到实车

迁移的是算法、接口和经实测调整的参数；进入新的真实房间时重新建图，不加载虚拟房间的地图。继续使用同一组 ROS 接口，把 Gazebo 的 `/scan`、`/odom`、TF 和模拟底盘替换为真实驱动，关闭仿真时钟。SLAM、探索、Nav2 和任务进程部署车端，电脑接收显示数据。[项目约定](../AGENTS.md)

先核查真实运动学、车体尺寸、轮径轮距、雷达安装位置、里程计误差、时间戳和控制延迟；当前差速仿真及原地转向不代表实车已具备相同能力。随后测量传感器噪声与丢帧、轮滑、制动距离和 RDK X5 负载，补入仿真扰动，再在新实物房间低速复测。对于 RL，训练布局与测试布局必须分开；对传感器误差及动力学做随机化是可研究方向，效果仍需实车测量。[动力学随机化原论文](https://arxiv.org/abs/1710.06537)

## 6. 地图和扫描过程如何呈现

RViz可实时显示地图、激光、车姿及规划路径；普通自主探索还会自动打开过程网页，显示逐步地图、激光、车头偏角、已走轨迹、规划路线与任务状态。时间轴只显示当时已记录的内容，位置TF过期时车位隐藏、轨迹断开。网页关闭不会停止算法。

每次生成 `data/runs/<时间>_<布局>_spawnN/process.json` 与自包含 `replay.html`，后者可直接双击。运行中网址见启动终端和同目录的 `session.json`。普通探索没有独立真值评分；自动验收目录另含 `result.json`，网页将最终独立评分单独显示。原SSH相机/雷达监看网页的整合仍待实车阶段。

自动检查加 `--record` 会保存 `/scan /odom /tf /tf_static /map /exploration/status /clock /plan`，结束后实际检查八个话题的消息数。[数据路径与录包重放](../data/README.md)、[操作指南](操作指南.md)
