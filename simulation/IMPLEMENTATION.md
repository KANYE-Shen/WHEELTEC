# 房间建图、导航与探索实施计划

**目标：** 在已有房间中完成可操作的建图、地图保存、AMCL 重定位、Nav2 目标导航和前沿探索。

**架构：** 保留 Gazebo/ros_gz 的传感器接口。SLAM Toolbox 提供 /map 与 map→odom；Nav2 根据激光和估计位姿规划、控制；探索节点只选择目标。保存地图、位姿图和参考方向，重启时切换 AMCL，避免两个节点同时发布 map→odom。

**技术栈：** ROS 2 Humble、Gazebo Fortress、SLAM Toolbox 2.6、Nav2 1.1、Python/rclpy。

用户已在 PLAN.md 确定路线，本轮明确要求继续接入，按以下步骤执行。

- [x] 添加闭环检查：收到有效地图与 TF，导航多目标，保存地图，重启 AMCL 后再次导航。先运行记录缺少建图能力时的失败。
- [x] 扩展 simulation/launch/room.launch.py：interfaces、mapping、localization 三模式；建图与 AMCL 互斥；启动 Nav2 与地图保存服务；测试使用独立通信域。

## 验证结果

- 建图四目标与重启定位后一目标全部成功，实际位置由Gazebo独立真值核对，误差12.6–17.3厘米。
- 自主探索自动到达4个观察目标，已知空地22.713平方米，保存栅格地图、位姿图和参考方向后返回起点，误差15.3厘米；最终状态completed。
- 临时箱子绕行、封路静止等待、移除障碍后原任务继续、取消停车及保存地图不变通过。详见 setup/verification 下的导航、探索、障碍摘要。
- 12个探索规则测试和6个遥控测试通过，遥控测试包含真实ROS进程中Ctrl+C后的零速度。
- Gazebo/RViz实际窗口和离线HTML操作指南均已截图查看。

返航失败定位到SLAM Toolbox 2.6.10的纯平移扫描预过滤；将minimum_travel_distance设为0，保留0.1秒处理间隔。另为成功观察位置添加访问记录，避免相邻目标循环。修复后重跑导航和探索闭环。

本轮实现、功能验证、操作说明与结果记录已整理提交并同步GitHub；实车核查和网页整合按PLAN继续。

封路恢复使用项目行为树：保留障碍观测，每5秒等待后再规划，最多60次。实测进入Wait后3秒内平移及转角均为0，移除挡板后原目标成功，误差15.5厘米；独立取消任务后停止。启动时将XML从项目源生成临时ASCII路径，处理Humble参数重写的中文路径问题，退出清理。
