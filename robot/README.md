# 地瓜派部署与只读核查

实车主要算法部署在 RDK X5：传感器、建图、定位、自主探索、Nav2、任务执行和底盘控制在车端运行，电脑负责显示和下发目标。车端服务独立于 SSH 会话。

已完成雷达/相机只读采样；时钟与相机源时间异常、odom/TF缺失，阶段一未完成。车端导航/运动安全服务尚未部署，尚无真实底盘测试结果。证据见[现场测量表](现场测量表.md)。

## 现行三阶段（2026-10-29）

阶段一：连接订阅、安全验证和校准；阶段二：人工参考建图、SLAM Toolbox/Nav2验证；阶段三：自主探索建图。完整范围、读数及停止/回滚见[准入清单](准入关卡.md)。当前阶段一未完成，无新运动批准。旧G6–G9建议已取消，历史编号不作为现行待办。

## 先检查现有接口

[inspect_interfaces.py](inspect_interfaces.py) 只订阅雷达、相机、里程计和 TF，检查实际消息频率、数据新鲜度、时间戳、坐标变换及主机资源。它不启动驱动、不发送运动指令、不修改车端配置。

将该脚本放到小车后，在已加载真实 ROS 环境、现有驱动正在运行的 SSH 终端执行：

```bash
python3 inspect_interfaces.py --seconds 15 --output ~/wheeltec-interface-check-01.json
```

沿用真实驱动的 ROS_DOMAIN_ID。默认话题 /scan、/odom，坐标 odom、base_link；雷达坐标取自收到的 LaserScan。名称不同时明确指定：

```bash
python3 inspect_interfaces.py --scan-topic /实际雷达话题 --odom-topic /实际里程计话题 --base-frame 实际车体坐标 --odom-frame 实际里程计坐标 --seconds 15 --output ~/wheeltec-interface-check-02.json
```

默认检查门槛为雷达5Hz、里程计10Hz；报告同时保留实际频率。频率不满足时先查驱动、负载和消息时间，不能仅降低门槛就认定系统可用。报告区分消息接收频率和时间戳前进的新测量频率，重复转发旧数据不算新测量。三个以上新消息、数据年龄不超过1秒、时间戳不为零且不倒退、雷达时间点上的 TF 可用，是接口初查条件。需要查询 map→odom 的建图/定位能力在后续任务验证中检查。

`interface_check_passed` 仅表示本次接口采样通过；`deployment_ready` 保持 false，直到下面的实测与运动验证完成。返回码0表示接口检查通过，1表示不满足或发生错误，130表示手动中止。每次使用新输出文件名，保留上一次结果。

工具验证在仿真中使用 --simulation，并明确记录 simulation=true。不要把仿真报告当成 RDK X5 实测结果。

## 上实车之前补齐哪些测量

使用 [现场测量表](现场测量表.md) 记录真实运动学、尺寸、雷达外参、里程计误差和停车距离。先确定底盘是差速、阿克曼还是其他形式；当前仿真允许原地旋转，实车是否具备该能力尚未核实。

测量完成后配置真实 footprint、运动约束、速度和传感器噪声，关闭仿真时钟，将 Gazebo 接口替换为真实驱动。按阶段一校准、阶段二人工建图与导航、阶段三自主探索的顺序进行有人监督的低速验证；先独立保存人工参考图，自主图不得覆盖。

同时运行雷达、视频、SLAM和Nav2后再采集资源与频率，比较驱动初查与完整系统的负载。由此决定地瓜派运行参数。


## 本轮车端静态准备

已编写 launch/robot.launch.py、systemd 服务模板、watchdog.py、velocity_smoother/collision_monitor 配置和 operator_bridge.py，未部署、未启动。车端footprint与探索半径也从同一校准JSON生成，车体长宽必须有measured证据，不再另填一套尺寸。config/robot.json 默认硬件未验证、控制话题和心跳N为空，preflight 拒绝运行。完整导航入口为阶段二（--gate 2），探索为阶段三（--gate 3）；阶段一（--gate 1）内部先架空确认停车，再低速校准，不要求先有尚待采集的制动结果；阶段二/三必须有阶段一完整校准与制动实测。admission_protocol必须为three-stage-20261029，人工批准按准入清单的新协议匹配，旧记录不自动转换，agent不得创建批准记录。

速度链为 Nav2 → /safety/nav_cmd_vel → velocity_smoother → /safety/smoothed_cmd_vel → collision_monitor → /safety/collision_cmd_vel → watchdog → 实测驱动话题。驱动话题必须只有最终看门狗控制；底盘自身的失联超时必须验证，才能覆盖进程被强杀或断电时软件无法发零的问题。二维雷达不能替代硬件急停，盲区、悬空物及地面障碍仍需现场监督。

看门狗使用本地单调时钟，50Hz输出；启动保持零速，明确解除保持须心跳新鲜、当前命令为零且急停释放。心跳/命令超时锁定停车，连接恢复不自动续行。急停信号解除也不会自动行驶。心跳N仍待阶段一安全验证前明确配置，0.5s命令超时及0.1m/s上限是模板限制，尚无实车停止距离证据。

systemd 模板由系统管理器驻留，独立于SSH；Restart只重启为停车保持，不恢复任务执行。模板没有安装脚本，不得直接enable/start。安装时需确认账户、驱动超时、ROS域、文件属主和0600环境凭据；Windows挂载文件权限不代表Linux部署权限。本轮仅语法及systemd配置静态检查。

网页桥只绑定127.0.0.1:8765，必须提供至少32字符私密Bearer token和明确HTTPS Origin；仅开放状态、人工心跳及停车，不开放速度、解除保持或导航目标。由现场配置的HTTPS反向代理同源转发，token保存在服务环境文件，不进入URL/日志/源码。不能把周期性后台服务当作操作者心跳；页面失联或无人监督必须停止发送。现有过程查看器仍只读。ROS图本身未实现SROS2安全隔离，不得开放到不可信网络。

阶段步骤与边界见[实车准入清单](准入关卡.md)。已取得网页只读连接与雷达/相机采样证据；运动链路、停止距离、运动桥端到端认证和算法满负载未验证。


## 新网页终端的车端模板

电脑使用 [console/](../console/README.md) 通过 SSH 隧道访问 localhost:8767。`start_console.sh` 和 `systemd/wheeltec-console.service` 仅为未安装模板，默认只读；没有 robot-config 时不创建速度或心跳发布器。密码和访问令牌不写入仓库；令牌文件须0600。系统服务与 SSH 独立，不因浏览器关闭而停止传感器或导航。

`launch/manual.launch.py` 是阶段一/二的独立手动安全链（gate仅1/2），不含 Nav2 控制器或探索器速度源；使用既有 preflight、实测尺寸和最终 watchdog。只验证了文件编译、shell语法及 ROS `--show-args` 加载，未启动实车节点。实际速度链、急停、驱动失联超时和停止距离须现场按关卡验证。完整 SSH shell 可执行账户允许的命令，网页互斥不能代替驱动安全与人工纪律。


安全审查补充：实车只读模式不创建底盘停止能力，不能把“释放网页租约”当作底盘停车确认。只读时软件停车按钮禁用，空格不发送底盘请求；维护PTY拒绝开启。配置并通过对应关卡的安全链后，PTY必须等待最终watchdog在停止请求之后新的、未解锁的状态确认且输出仍独占；缺失确认则保持关闭。完整Shell仍是账户权限。此限制来自已批准计划的“维护终端启用前先停车”，不能用未验证的停止能力绕过；实车已做只读采样，运动与真实watchdog确认仍未验证。补强增加了先失败后通过的HTTP/WS回归，后端共25/25。最近完整真实仿真为补强前9/12；补强后完成单元回归与构建，真实watchdog确认分支未经实车验证，不把旧仿真结果称为该分支的实测证明。
