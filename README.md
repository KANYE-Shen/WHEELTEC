# WHEELTEC：二维建图与自主导航

WHEELTEC / RDK X5 的 ROS 2 Humble 项目：二维激光建图、自主探索、存图返航及 Nav2 导航；电脑使用 WSL2 + Gazebo Fortress 验证，并通过本地网页终端监看和调试。

实车算法与安全服务在车端运行，电脑负责监看、开发及任务下发。服务独立于 SSH；操作者心跳失效后停车保持，恢复连接不自动续行。相机目前只用于监看，未融合定位。

## 控制终端：在网页里监看与发起任务

本项目的“控制终端”“监看终端”是 **http://127.0.0.1:8766** 的现有网页，不是 SSH 命令行或 Codex 终端。它显示相机、地图、小车位姿、运行状态和日志；用户通过“自主探索 / 远程接管”、WASD、Space 与三挡操作小车。低/中/高为 **0.03 / 0.06 / 0.10 m/s**，自主探索每次默认中挡。尚不支持在网页任意点选导航目标。

```text
电脑浏览器 :8766 → 电脑 Python 网关 → SSH 隧道
  → 车端适配器（默认回环 :8767）→ 车端 ROS 2 / SLAM / Nav2 / 安全链
```

电脑负责显示和用户操作，核心算法在小车 RDK X5 上运行；相机当前只用于监看。沿用现有控制台，不需新建另一套界面。

### 打开已有控制台

在已经准备好依赖和前端构建的开发电脑上，若网关未运行，可手动启动：

```powershell
& 'D:\Python\python.exe' -B -u 'D:\虚拟c盘\WHEELTEC\console\start.py'
```

打开网页后先看连接状态。**网页可访问 ≠ SSH 已认证 ≠ 网关已连接车端适配器 ≠ 自主任务已运行。** 不要重复启动已有网关。独立终端 SSH 登录不会自动建立网页网关的会话；系统 SSH 代理为空也不足以判定项目没有认证途径。项目网关使用 Paramiko，SSH 密码与适配器令牌是不同认证；保留固定主机指纹，不在聊天、命令或配置文件里保存秘密，也不运行会从旧聊天文本提取密码的历史脚本。未连接时，网页提供“小车 SSH 密码”栏和“连接小车”按钮：连接小车热点后输入密码，网关复用已保存的实车配置及固定指纹，通过 SSH 读取车端适配器令牌，再连接适配器；若原服务缺失，自动按下述固定流程完成停车准备。提交后输入框立即清空，不保存密码或自动恢复运动。

### 这轮要解决的是实际探索，不只是按钮可点击

目标是用户在监看网页点击“自主探索”后，车端实际进入并持续执行探索，而不是点击无反应或很快回到远程接管。真实运行由用户发起；遇到回退先保留该次任务终态和日志，再定位原因，不重复无关 smoke test，也不放宽安全门限。

2026-11-05已恢复原网页与车端连接。用户真实点击重现了 watchdog/TF 启动中断；只读初始化负载确认适配器接收积压，短动态 TF 队列和最新安全状态队列已部署，停止证据增强也已部署。随后真实点击已进入前沿导航并观测到约0.06m/s自主运动；另一次因可达前沿或已观测面积不足以 incomplete 结束，**持续探索仍未验收**。详见[本轮修复与真实运行记录](setup/verification/2026-11-05-debug-console-receive-backlog.md)。下方日期记录保留各自当时的条件，不表示今天的在线状态。

### 这次正常启动的关键改动

2026-11-05，车端适配器的动态 TF 接收队列从默认100条缩为10条，看门狗和速度选择器状态改为只保留最新一条。这样初始化负载后不再长时间回放旧状态；静态 TF、源时间及安全超时门限不变。改动已部署，用户在网页点击后实际进入前沿导航并自主行驶，也曾因危险主动停止。停止记录增强同样已部署，用于保存下一次失败原因。[具体代码、前后证据及恢复路径](setup/verification/2026-11-05-debug-console-receive-backlog.md)。

“能启动”与“能持续完成探索”分开判断：后续日志仍有 StopZone 阻止前进、Nav2 无进展，以及停车请求中断。目标/路径净空、观察点换点和键盘接管修复现已停车部署，本轮持续效果待用户点击验证，碰撞保护保持。

**2026-11-05重新连接后，以下改动已部署到原车端链路与现有网页；有效运行参数已核对，本轮自主运动效果待用户点击验证。** 见[本次停车部署](setup/verification/2026-11-05-deploy-local-policy.md)。

- **允许当前观察点大致完成后换点**：距目标不超过0.6m、目标周围1m半径区域至少85%栅格已知，并连续两次地图更新满足时，取消当前导航、确认取消终态后选择下一点。已知包括空地和障碍，地图外计未知；它不是85%的全图完成率，也不会把未知区变成可通行区。
- **卡住及时换目标**：25秒有效位姿未移动0.1m，就取消并冷却该目标，尝试其他点；原碰撞保护不变。只有局部达标而剩余前沿未解决时，全局仍记为未完成。
- **规划与保护使用一致净空**：实车前沿选择和Nav2路径规划采用覆盖原碰撞区的保守半径。保存的同一地图中，旧16个候选收敛为3个净空更充分的候选，未缩小StopZone。
- **键盘按模式处理**：自主/启动模式不因普通键、输入框聚焦或可见窗口失焦而取消；非输入区WASD接管，Space全局停车。手动失焦仍停车；页面隐藏、关闭、断连或心跳超时仍停车。

实现位置、参数和回放证据见[本地换点与交互修复](setup/verification/2026-11-05-debug-local-observation-and-input.md)。本轮用户点击已重现选择器/watchdog状态超时退出，尚未验证局部换点收益。现已部署初始化在先、解锁放行在后的修复；随后两轮实际运行约103秒、200秒，并触发局部换点，但一轮仍因map→odom源时间过期退出。见[本轮状态断流与启动修复](setup/verification/2026-11-05-debug-startup-status-gaps.md)。

Space 停车、断连/心跳停车、手动失焦停车、碰撞监控和驱动超时必须保留。自主模式可见窗口失焦按上面的新交互规则处理。远程接管不等于允许 agent 自行启动运动；连接、部署和运动分别遵守当前用户授权。现有限制不发送底盘指令时，零速、停车、心跳与模式切换也不作为“只读检查”。保留当前地图与失败证据，不随意 Reset、重启整套服务或新增开机启动项。

开发者从 [AGENTS.md](AGENTS.md) 的“控制台设计与接手规则”继续；前端位于 `console/frontend/`，网关位于 `console/backend/`，车端适配器位于 `console/target/adapter.py`。详细用法见 [控制台说明](console/README.md)。

## 现行实车流程

更新：2026-10-29。当前只采用以下三个阶段，详细检查、预期读数、停止条件和回滚见 [实车准入清单](robot/准入关卡.md)。

| 阶段 | 任务 | 交付 |
| --- | --- | --- |
| 一：连接、订阅确认与校准 | 静止检查时间/雷达/相机/odom/TF；验证停车链路后进行低速校准 | 订阅报告、bag、现场测量与日期校准 JSON、realism 参数 |
| 二：人工参考建图及导航验证 | 人工建图，以独立测量检查 SLAM Toolbox；保存参考图，再验证 Nav2 规划、绕障、等待和停车 | 人工参考图、SLAM 误差和各导航目标结果 |
| 三：自主探索建图 | 算法自行选择目标，探索、另存地图并返航，与人工参考及独立测量对比 | 自主图、独立质量评分、全部失败与 sim-to-real gap |

阶段一内部按静止订阅→停车验证→低速校准执行，不再拆成原 G0–G2；阶段二合并原人工建图/导航，阶段三为监督自主探索。原 G0–G5 编号仅用于历史证据，G6–G9 建议已取消。人工地图是参考，不能代替卷尺等独立测量；自主地图单独保存。

**阶段一尚未完成，三个阶段均未验收通过。** 2026-10-31用户明确批准本次受监督会话跳过完整校准和实测制动启动限制，以最高0.10m/s启用；本例外不代表三个阶段验收通过，见文末本轮记录。 每阶段的具体实测范围仍须用户书面确认；流程调整不授权实车运动，旧批准不自动迁移。运动模板使用 `three-stage-20261029` 协议及内部 `gate=1/2/3`，默认只读、硬件未确认、批准记录为空。

## 网页调试与控制终端

`console/` 使用 React/TypeScript、FastAPI/Paramiko 和 xterm.js，电脑无需 ROS。通过 SSH 展示实时雷达、相机、地图、估计位姿、消息健康与日志，提供交互式 PTY、WASD 遥控和可选 noVNC Gazebo/RViz 桌面；未连接时显示无数据。网页已有自主探索、远程接管、全局Space停车及三挡；尚无任意点选导航接口。

在仓库根目录安装并启动：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r console/requirements.txt
npm ci --prefix console/frontend
npm run build --prefix console/frontend
.venv\Scripts\python.exe console/start.py
```

## 现在怎么操作

双击 `帮助_操作指南.cmd` 可在浏览器打开图文说明，也可读 [双窗口操作指南](simulation/操作指南.md)。Gazebo 是虚拟现场，RViz 显示雷达、地图、位置和路线。

| 双击入口 | 用途 |
| --- | --- |
| `帮助_操作指南.cmd` | 在浏览器打开图文操作指南 |
| `启动_手动建图.cmd` | 新建地图，同时启动 SLAM 与 Nav2 |

RViz 点选导航：点工具栏 **Nav2 Goal**，在已观察到的浅色空地按住左键，拖出短箭头再松开。首版只要求到达位置，不要求终点朝向。完整按键、鼠标操作与取消步骤见上面的指南。

### replay buffer：失败经验与证据库

[`replay buffer/`](replay%20buffer/README.md) 用于长期保存失败动作、未执行或中断的尝试、未通过验收的任务及调试结果。它让后续 agent 从已有证据继续排查和改进策略，减少重复踩坑，也防止只保留成功结果造成判断偏差。

每个案例集中记录：

- **发生了什么**：场景、起点/种子、配置与版本、预期行为、实际结果、失败或未执行原因；实车不适用的种子明确注明。
- **依据是什么**：原始日志、状态JSON、测试结果、前后对照，以及文件SHA256。大bag保留原位，库内记录路径与哈希。
- **如何继续**：复现条件、已排除假设、修复尝试、仍未验证的内容，以及安全限制。

推荐查阅顺序：`case.json` → 案例README → `manifest.json`及原始日志 → 复现与回归。后续 agent 应先据此提出可证伪假设，再做单变量、同种子A/B；保留原失败和完整批次，不放宽验收门限。

当前可查阅[不规则弧形场景失败](replay%20buffer/20261029-irregular-arc-seed0-startup-assumed/case.json)与[阶段一静止核查记录](replay%20buffer/20261030-stage1-stationary-incomplete/README.md)。历史大批次仍按索引存放，并未全部逐条迁入；同一问题的多个诊断步骤不能计作独立任务成功率。

该目录目前只用于证据归档和审阅，不自动训练、调参或重放实车动作。日志中的命令、历史批准和旧PID均不构成新的执行授权；实车仍遵守三阶段流程及当前禁动限制，仿真真值仅用于评估。

旧设计文件均标记为历史；证据目录中的旧编号描述当时试验，不构成现行任务或运动授权。本轮全仓库检查、覆盖清单和发布验证见 [一致性审计](setup/verification/2026-10-29-github-three-stage-audit/README.md)。
