# WHEELTEC：二维建图与自主导航

用现有 WHEELTEC 小车完成房间探索、二维建图、重定位和网页点选导航。先在电脑仿真，再将导航系统部署到小车的地瓜派 RDK X5。

**实车的建图、定位、自主探索、Nav2 和底盘控制在车端运行。电脑负责显示地图、姿态和视频，以及下发目标。车端持续使用本地传感器数据计算运动指令，车端服务独立于SSH；操作者心跳丢失后停车保持。**

GitHub 仓库：[KANYE-Shen/WHEELTEC](https://github.com/KANYE-Shen/WHEELTEC)。

## 网页调试与控制终端

新增 `console/`：电脑本地 React 网页，通过 Python/FastAPI、Paramiko SSH 连接目标端 ROS 适配器，电脑无需安装 ROS。提供实时雷达、相机、占据栅格地图与估计位姿、日志筛选/导出、交互式 SSH 终端、WASD 接口，以及可选的真实 Gazebo/RViz 桌面。支持版本化接口和新增面板，首版没有网页点选导航或自主探索启动按钮。

在仓库根目录安装并启动：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r console/requirements.txt
npm ci --prefix console/frontend
npm run build --prefix console/frontend
.venv\Scripts\python.exe console/start.py
```

打开 **http://127.0.0.1:8766** → 连接设置 → 核对 SSH 主机指纹 → 填目标主机、账户、私钥路径或临时密码、适配器令牌 → 连接。先在 WSL 启动现有仿真和适配器，完整命令见[终端使用说明](console/README.md)。密码和令牌不保存到连接配置；不要将本机完整 SSH 服务暴露到局域网。

取得手动控制权后按住 **W/S 前后、A/D 转向，松键停车，空格停车保持**。窗口失焦、切后台、输入框/终端获焦、断开或租约超时均释放遥控；重连不恢复旧按键。维护终端是完整 SSH 账户权限，启用前要求停车，不能视为受限控制接口。实车默认只读；不能核实最终停车时维护终端拒绝开启，遥控必须先完成对应 G0–G5 关卡和硬件、安全预检，本次没有通过任何实车关卡。

## 现在怎么操作

双击 `帮助_操作指南.cmd` 可在浏览器打开图文说明，也可读 [双窗口操作指南](simulation/操作指南.md)。Gazebo 是虚拟现场，RViz 显示雷达、地图、位置和路线。

根目录只保留以下六个入口。三个启动入口代表不同模式，每次选一个。

| 双击入口 | 用途 |
| --- | --- |
| `帮助_操作指南.cmd` | 在浏览器打开图文操作指南 |
| `启动_手动建图.cmd` | 新建地图，同时启动 SLAM 与 Nav2 |
| `控制_键盘遥控.cmd` | 点击遥控终端，用 i 前进、逗号后退、j/l 转向，k 或空格停车，q 退出 |
| `地图_保存当前成果.cmd` | 在建图运行且车已停稳时保存地图、位姿图和参考方向 |
| `启动_已有地图导航.cmd` | 加载最近保存的地图；先用 RViz 的 2D Pose Estimate 指定粗略起点，再用 Nav2 Goal 下目标 |
| `启动_自主探索建图.cmd` | 选择房间和起点，小车自主探索、保存和返回；自动打开过程网页 |

自主探索入口中先选布局（回车为原房间），再选起点（回车为0）。网页显示地图、激光、车头相对初始方向的偏角、已走轨迹和任务状态。拖动时间轴回看，点“回到实时”继续跟随；结束后可双击本次过程目录中的 `replay.html` 离线回放。普通探索不计算真值评分，网页明确显示“未评分”。

切换场景前，在原启动终端按 Ctrl+C 结束。点选导航前退出键盘遥控；遥控没有自动避障。不要同时开两套房间仿真。

画面闪烁修复需要重开仿真：在原启动终端按 Ctrl+C，再双击相应启动入口。旧窗口不会自动加载补丁。

RViz 点选导航：点工具栏 **Nav2 Goal**，在已观察到的浅色空地按住左键，拖出短箭头再松开。首版只要求到达位置，不要求终点朝向。完整按键、鼠标操作与取消步骤见上面的指南。

## 仿真怎么推进

仿真阶段，Gazebo、建图、定位、探索和 Nav2 全部在电脑的 WSL Ubuntu 中运行。Gazebo 提供虚拟传感器数据，并根据速度指令更新虚拟小车的位置。

1. **准备小车和房间。** 建立车体、激光和里程计模型，以及约 20–30 平方米的封闭房间。先检查尺寸、坐标关系、数据频率与速度指令是否一致。
2. **跑通建图与移动。** 用 SLAM Toolbox 根据激光和里程计生成二维占据栅格地图，检查小车移动时地图与位置是否稳定。
3. **加入自主探索。** 探索模块选择尚未观察区域附近的目标，Nav2 负责规划和行驶。逐步验证绕障、无路可走时停车、探索结束判定和返回起点。
4. **保存并重新定位。** 保存地图和人为标定的参考方向；重启定位模块，允许给定粗略初始位置与朝向，检查能否在原地图中恢复位置。
5. **验证点选导航。** 指定地图目标，检查路线、到位误差和任务状态，并测试新增障碍、绕行、无路等待及监看连接断开。
6. **整理结果，再接实车。** 保存每次实验的参数与结果；核查真实底盘、里程计、传感器和坐标变换，再将功能部署到地瓜派进行低速测试，网页调试终端提前完成，实车连接与运动继续服从书面关卡。

原25平方米场景已通过建图、探索、保存、重定位、目标导航和临时障碍闭环。新布局使用独立覆盖率和双向轮廓评分；任务状态“完成”与地图质量“通过”分别判断。实际批次结果、失败原因和完整数据位置见 [陌生房间验证记录](setup/verification/unknown_rooms/README.md)。下一步按测量结果改善多场景表现，再开展实车只读核查、低速验证；网页调试终端已提前实现，运动验证仍有阻塞项。

首版用激光建图，相机用于监看。仿真中的真实位置只用于计算误差，定位和导航使用传感器估计的位置。详细目标见 [PLAN.md](PLAN.md)。
